# 发版闸（Shipgate）

骨架：发版申请入闸 → 环境晋升裁决 → 放行/回滚窗 → 发布结果对账

- 前端 http://127.0.0.1:6800
- API http://127.0.0.1:11800
- 数据库环境变量 `SHIPGATE_DB`（容器内默认 `/data/shipgate.db`）

```bash
docker compose up -d --build
```

## 入闸后流水线翻红的命运（已固定为「翻红即冻结」）

实现方在两条命运行为中二选一并全程贯彻，本仓库选定 **臂一：翻红即冻结（fail-closed）**，
不会在两种语义间切换：

- 流水线变红（且发版单已入闸、在途或已落地）即把该发版单 **冻结**，晋升写口整笔失败；
- 在途单 **保留**、不消失，但 **不得再向更高环境推进**，总览显式露出冻结；
- 冻结为 **粘性**：事后再翻绿也不解除，只有重新走流程才能继续；
- 入闸当下的红/绿闸是另一条独立规则（`入闸须流水线绿` 设置），本机制只管「入闸之后」变红。

### 数据字段（releases）

| 字段 | 含义 |
| --- | --- |
| `pipeline_snapshot_at_admit` | 入闸当时的流水线结论（入闸快照，入闸即定格） |
| `frozen` | 冻结标，入闸后翻红置 1，粘性，不随翻绿解除 |
| `red_after_admit_at` | 入闸后首次翻红时间戳；重复翻红不覆盖首次时间 |

晋升被拒时，`promote_events` 写一条 `decision='拒绝'` 且 `note` 为拒因，审计同时记录「晋升拒绝」，
因此 **拒绝永远留痕、可重放、可核**。

### 同一命运（流水线 / 发版单 / 晋升写口 / 总览 / 对账 / 审计）

- 发版单流水线区、晋升页、总览在途格、对账冻结清单、审计流水都展示同一组快照/冻结标/翻红时间/拒因；
- 总览在途 **保留** 冻结单（翻红后不再从总览消失），并单列「冻结数」；
- 对账提供「冻结清单」与「晋升拒绝清单（拒因可核）」。

### 并发与半截脏写收口

- 翻红写口（`/流水线`）与晋升写口（`/晋升`）都以 `BEGIN IMMEDIATE` 取同一把写锁，
  并发的翻红与晋升被串行化，**只有一个结局，不会双写**；
- 晋升在单事务内完成事件、状态、名册、实例写入，中途异常整笔回滚，
  不会留下无痕迹的高环境晋升（半截脏晋升必收口）；
- 数据库启用 WAL（单写多读）+ `busy_timeout`，配合写锁降低并发写竞争。
